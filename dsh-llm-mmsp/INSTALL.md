# 安装说明（给接收方）

本插件让 DeepSeek Harness（DSH）直接用 **MMSP 协议**调用 `go.penguin.ooo` 等上游。

---

## 一、环境要求

| 项 | 要求 |
|---|---|
| DSH | 0.2.0-rc.1 或 0.2.1-rc.2（`@deepseek-ai/dsh-llm` 的版本范围） |
| Node | 与 DSH 自带的一致即可，无需单独安装 |
| 一个 MMSP 服务端 | 默认 `https://go.penguin.ooo`，也可以是别的 MMSP 兼容端点 |
| 至少一个密钥 | 由你的上游账号提供 |

---

## 二、安装

在**你自己的机器**上，把拿到的 `.tgz` 放好，然后任选一种：

### 方式 A：命令行（推荐）

```bash
dsh plugin --profile <你的profile名> add ./dsh-llm-mmsp-0.4.0.tgz
```

`<你的profile名>` 通常就是 `desktop`（DSH Desktop）或你自定义的 profile。
装完**重启 DSH**。

### 方式 B：让 DSH 里的 AI 助手装

在 DSH 会话里说：

> 把 `C:\路径\dsh-llm-mmsp-0.4.0.tgz` 这个插件装上

助手会调 `plugin_manager` 的 `install_bundle` 完成安装。

### 方式 C：解压到 plugins-src（适合要改代码的人）

```bash
# 1. 解压
tar -xzf dsh-llm-mmsp-0.4.0.tgz -C <你的plugins-src目录>
# 得到 <你的plugins-src目录>/package/  —— 重命名成 dsh-llm-mmsp

# 2. 再用方式 A 或 B 安装那个目录
```

## 三、配置（装完必做）

### 3.1 填上游和密钥

打开 **设置（左下角齿轮）→ 左侧分区栏的「MMSP」**：

```
路由名        [mmsp                    ]   ← 一般不用改
上游地址      [https://go.penguin.ooo  ]   ← 换服务端才改
```

然后往下滚到 **密钥** 区：

```
[粘贴密钥]  [添加密钥]
直接粘贴密钥即可 —— 会自动分配一个内部引用名，不用你起名字。
```

**粘贴你的密钥，点「添加密钥」**，就完事了。界面会自动：
分配引用名 → 写入 DSH 凭据库 → 加进列表 → 保存配置。

### 3.2 多密钥（可选）

同一个页面可以加任意多条密钥。列表默认**一次显示 4 条**，多出来的滚动查看：

- **拖拽**行调整顺序 —— 顺序就是优先级，拖完点「保存顺序」
- **⏸ / ▶** 临时停用某条（点完立即生效）
- **✕** 删除这一行（**连凭据值一起清掉**，点完立即生效）
- **换值**：在输入框粘贴新密钥，行内会就地长出「更换」按钮
- **轮询策略**：
  - `round-robin`（**默认**）—— 每次请求换下一个，把负载摊到多个账号
  - `priority` —— 始终用最靠前的，失败才降到下一个

### 3.3 思考等级

档位选择器里有六档（`关闭 / 低 / 中 / 高 / 极高 / 最高`），直接对应 MMSP 的
`thinking_level`，选什么就发什么，插件不做降级。

同一区域还有一个 **思考摘要** 开关，默认「显示思考过程」：

- Gemini 系**不开**它就只计费 `thoughts_tokens`、一个字的思考都看不到
- 开启**不会**增加 token，只是把已经计费的思考显示出来

> 唯一例外：`gemini-4-argon` 收 `none` 会报错，所以它的选择器里没有「关闭」
> （会自动用 `low` 代替，效果等同不思考）。

### 3.4 怎么确认在正常工作

- 密钥区顶部有 **实时用量条**：`累计成功 N 次 / 上次用 X / 下次用 Y`
- 每行密钥后面有 `用 N 次`、`冷却 Ns`、`刚用过 / 下一个` 等标记
- 模型选择器里能看到 `MMSP (Penguin)` 这一组，以及 12 个左右的模型

## 四、验证装好了

1. 打开 **设置 → MMSP**，能看到上面那些表单 → 说明插件激活了
2. 模型选择器（输入框上方）里选 `mmsp/deepseek-flash`
3. 随便发一句话，能收到回复 → 通了

如果模型列表是空的：
- 检查「上游地址」是否正确
- 检查密钥是否填了（用量条上 `累计成功 0 次` 且各条都没值 = 没配密钥）
- 看 **设置 → MMSP** 里密钥行的状态点：绿=已配置，红=没值

---

## 五、卸载

```bash
dsh plugin --profile <你的profile名> remove dsh-llm-mmsp
```

或在 DSH 的**插件管理**页面找到 `MMSP 协议适配`，点「卸载」。

> 卸载**不会**删除你存在凭据库里的密钥（`~/.dsh/.credentials.yaml` 的 `refs:` 段）。
> 要彻底清理，手动删掉 `MMSP_API_KEY*` 那些行。

## 六、常见问题

**Q：装完了设置里找不到 MMSP？**
A：先 `Ctrl+R` 刷新页面。客户端插件在页面加载时才会注册。

**Q：密钥填了但还是报 `MISSING_CREDENTIAL`？**
A：确认密钥行的状态点是绿的。如果是红的，在该行的输入框里粘贴一次密钥，
点「更换」写出新值。

**Q：能连别的上游吗？**
A：能。只要那个服务端实现了 MMSP 协议（`POST {base}/api/v1/stream`、
`GET {base}/api/v1/models`），改「上游地址」即可。但协议细节是按
`go.penguin.ooo` 实测校准的，别的服务端可能需要适配。

**Q：`round-robin` 下为什么有的 key 用得多有的用得少？**
A：轮换**跳过**了正在冷却的、以及被停用的 key。另外计数是内存态，
DSH 重启就归零。

## 七、它做了什么（技术概览）

- **Host 半边**（`lib/index.js` + `lib/mmsp-adapter.js` + `lib/mmsp-protocol.js`）
  实现 DSH 的 `LlmAdapter`，把 MMSP 事件流翻译成 DSH 的 chunk
- **密钥池**（`lib/key-pool.js`）负责优先级排序、轮询游标、60 秒冷却
- **Client 半边**（`lib/client.js`）提供上面那些设置界面
- 密钥值存在 DSH 凭据库，配置文件里只有引用名

更细的协议说明、实测结论和已知限制见包内的 `README.md`。
